# 三、新增 3D Agent 动态执行实验室

新增独立页面，产品名称：

**DeepSeek Agent Execution Lab**

中文名称：

DeepSeek Agent 动态执行实验室。

采用以下设计：

3D 场景 + 动态执行流水线 + 实时输入台 + 源码追踪 + 数据观察器 + 原理知识库。

## 3.1 3D 主场景

建议使用 Three.js / React Three Fiber。

创建一个具有空间感的 3D Agent 执行环境。

包含多个独立站台。

初步考虑：

01 用户输入
02 消息接收
03 Session 管理
04 Agent Inbox
05 Turn 初始化
06 Context 构建
07 Prompt 构建
08 LLM Request
09 LLM Streaming
10 Tool Call 解析
11 Tool Registry
12 Tool Execution
13 Tool Result
14 Agent Loop 判断
15 Assistant Response
16 Session Event
17 UI 输出

注意：这些是展示结构的初步构想，不代表真实执行顺序。

最终必须根据 DeepSeek Harness 本地源码，确认各阶段实际对应的模块、方法、事件和执行关系。

## 3.2 3D 站台设计

不同模块使用不同的视觉模型。

例如：

- 用户输入：消息输入终端。
- Session：会话数据存储舱。
- Agent：Agent 核心控制中心。
- Prompt：上下文数据汇聚装置。
- LLM：模型计算中心。
- Tool Registry：工具调度中心。
- Shell：终端执行环境。
- Filesystem：文件系统。
- Session Event：事件日志存储装置。
- Output：最终回答输出终端。

站台之间通过管道、连线或数据传输通道连接。

每个站台展示：
- 名称
- 编号
- 简短说明
- 当前执行状态
- 数据入口
- 数据出口

不要只是把现有的 2D 节点图简单转换成 3D 方块。

需要有真正的空间布局和视觉层次。

## 3.3 动态数据流

这是整个实验室的核心。

当用户开始执行一个任务：

- 数据粒子从入口发出。
- 粒子沿着连接路径移动。
- 经过的站台依次激活。
- 当前站台显示执行状态。
- 完成后数据继续传输。
- 出现 Tool Call 时进入工具执行分支。
- 工具完成后返回 Agent Loop。
- 最终回答进入输出站台。

需要支持：
- 动态粒子
- 管道流光
- 节点激活
- 数据传输动画
- 分支动画
- 循环回流动画
- 失败状态
- 等待授权状态
- 最终输出动画

所有动画必须有明确的业务含义。

# 五、Agent Loop 动态循环

必须重点实现真正的分支和循环动画。

示意：

LLM Request
↓
LLM Response
↓
是否有 Tool Call？
├── 有
│   ↓
│ Tool Registry
│   ↓
│ Tool Execution
│   ↓
│ Tool Result
│   ↓
│ 返回 Agent Loop
│   ↓
│ 再次调用 LLM
│
└── 没有
    ↓
  Assistant Response
    ↓
  Turn End

需要支持：

- 多个 Tool Call
- 连续工具调用
- 工具执行失败
- 工具审批
- 用户中断
- 模型请求失败
- 循环继续
- 正常结束

通过动画清晰展示 Agent 如何反复调用模型和工具。

最终执行路线以实际源码为准。

# 十、两个学习模式之间的联动

这是本次新增的一个重要要求。

不能让动态实验室成为与原平台完全割裂的独立项目。

需要建立相互跳转关系。

例如：

原有平台：
- Agent Loop 页面 → 进入动态实验室的 Agent Loop 场景。
- LLM 页面 → 进入动态实验室的 LLM 场景。
- Tool 页面 → 进入工具执行场景。
- Session 页面 → 进入 Session 生命周期场景。
- 事件系统 → 进入相关事件执行演示。

动态实验室：
- 点击节点 → 查看真实源码。
- 点击源码文件 → 跳转到原有源码知识库。
- 点击相关事件 → 跳转到原有事件系统。
- 点击相关模块 → 跳转到原有架构图。

如果当前没有对应的页面路由，先检查现有结构，再设计兼容的跳转方式。

# HELIOS · 太阳系观测台

> 把 45 亿公里折进一屏，还能点开其中任何一颗。

一个**单页、零依赖、可离线打开**的交互式太阳系。太阳与八大行星都能点进去——
点谁，镜头就在 1 秒内飞到谁面前，滚轮继续推近，表面细节随缩放层级真的多算几层。

**直接双击 `index.html` 就能看。** 不需要服务器、不需要联网、不需要安装任何东西。

v1 之后按 [`提示词.md`](提示词.md) 的「追加需求 v2」做了升级：整座太阳系不再是静止的舞台，
而是一艘正在飞的船 —— 行星绕太阳、太阳绕银心、整艘船还在朝巨爵座方向以 369.82 km/s 飞；
按 `F` 可以换参考系，看见椭圆变成螺旋。滚轮能一路从行星表面拉到银河。

> v1 记录见文末「版本」小节；v2 新增的数字出处见 [`research/motion-sources.md`](research/motion-sources.md)。

## 一、它是什么

```
HELIOS · SOLAR SYSTEM OBSERVATORY
太阳系观测台
八颗行星按真实轨道运行，太阳在中心燃烧。点开任何一颗，走进去看。
```

三条承诺，缺一条都不算完成：

1. **位置是算出来的** —— 任一日期下，行星的位置来自 JPL 轨道根数 + 开普勒方程解出的真实椭圆，
   不是摆上去的装饰。改日期，位置真的会变。
2. **表面是画出来的** —— 没有一张贴图、没有素材图、没有视频。每一颗的表面都由
   fBm / 脊状噪声 / 细胞噪声在着色器里逐像素生成。
3. **九颗都能点开** —— 太阳 + 八大行星，点击 → 镜头飞行 → 特写 → 细节可再放大 → 一键返回。

**它不是**：九张详情卡片、一个贴了球贴图的轮播、或者一张会转的太阳系示意图。

## 一·五、四层运动（v2 的核心）

画面里同时有四种运动，每一层都有自己的参考系和量级：

| # | 运动 | 参考系 | 量级 | 出处 |
| --- | --- | --- | --- | --- |
| ① | 行星绕太阳 | 日心 | 88 天 – 165 年 | JPL Table 1 根数 |
| ② | 太阳相对邻近恒星（本动） | 局部静止标准 LSR | **19.4 km/s**，指向 RA 18h28m / Dec +30°（武仙座，靠近织女星） | NASA Sun Fact Sheet + Wikipedia: Solar apex |
| ③ | 太阳绕银心 | 银心 | **约 220 km/s**，**约 2.4 亿年**一圈，距银心 **约 27,000 光年（8.3 kpc）**，在猎户臂内侧 | Wikipedia: Milky Way |
| ④ | 太阳相对 CMB | CMB 静止系 | **369.82 ± 0.11 km/s**，朝巨爵座与狮子座边界 | Planck 2018 |

四层都在界面上有读数（右下角里程表），并且**四层用的是各自的模型**：
①用拟合根数，②③④用匀速直线/圆轨道近似。这一点在帮助浮层与 README 里都写明。

### 参考系（`F` 键循环）

| 参考系 | 减去什么 | 画面 |
| --- | --- | --- |
| `太阳静止` | 不减 | 行星走**闭合椭圆**（v1 的样子），轨道线也画出来 |
| `银河静止` | 太阳绕银心的位移 | 行星轨迹变成**螺旋**，日心椭圆线自动隐藏（那时行星已经不在椭圆上） |
| `CMB 静止` | 太阳相对 CMB 的总位移 | 螺旋整体再**漂移**（方向与绕银心不同） |

**相机留在参考系里，不跟着太阳走。** 这是关键：只有镜头钉在「银河」上，
太阳才会在画面里真的移动、行星才会在身后拖出螺旋。太阳快走出画面时（超过画幅 75%），
镜头才慢慢跟一下，其余时间一动不动 —— 所以运动是能看见的。
切到这两个参考系时时间倍率会自动落到「1 秒 = 1 年」并开始播放，否则看不出在动。

> 渲染坐标用「浮动原点」：位移累积到 3 万 AU 就把参考系原点挪到当前时刻并同步平移相机，
> 画面不跳，浮点精度也不会烂掉。

**为什么 CMB 参考系不把 220 + 19.4 再加一次**：369.82 km/s 本身就是绕银心与本动合成的总速度，
三者不在一条直线上（220 + 19.4 ≠ 369.82），叠加会重复计数。

### 螺旋与「轨迹放大因子」

太阳绕银心的真实速度是 **46.4 AU/年** ——一个地球年太阳要走 46 个地球轨道半径。
直接按真实比例画，画面里只会看到一条斜线，看不出螺旋。所以界面提供 **轨迹放大因子**：
把太阳漂移按 **1/N** 显示，让「轨道直径 : 螺距」回到能看出螺旋的比例。

- 默认 **×20**：漂移按 2.32 AU/年 画，与地球 2 AU 的轨道直径可比 —— 这时螺旋一眼就能看出来。
- 可选 ×1 / ×20 / ×100 / ×1000，控制面板里的「轨迹对照」插图同时画出**真实比例**与**当前比例**
  两种螺距，并写明「天文量没有变」。
- **放大只影响显示，不改任何读数**：里程表里的速度、弧长、距银心都按真实值算。
- 在 `比例压缩` 模式下，位移和轨道走**同一套** r^0.55 压缩，否则「压缩过的轨道 + 没压缩的漂移」
  会让螺旋和轨道不成比例。

### LOD 四档

| 档 | 尺度 | 内容 |
| --- | --- | --- |
| L0 | 天体特写 | 表面纹理、云层、环 |
| L1 | 太阳系 | 九颗天体 + 轨道 + 螺旋轨迹 |
| L2 | 恒星邻域（25 pc） | 1,503 颗带真实距离的恒星，随太阳移动产生视差 |
| L3 | 银河（约 30 kpc） | 程序化银河盘 + 太阳轨道圆 + 太阳当前位置 |

滚轮从 L0 一路拉到 L3 是连续的，跨档用淡入淡出，不黑屏。
L2 的恒星**只移动太阳、不编自行**：星表里没有自行数据，所以恒星位置是 J2000 静态值，
位移全部来自太阳的运动。L3 是一个独立的 kpc 坐标系，界面上标了「示意比例」。

## 二、怎么开

| 方式 | 做法 |
| --- | --- |
| 直接看 | 双击 `index.html`（`file://` 可开，控制台无报错） |
| 开发 | 打开 `dev.html`（外链 `src/`，改样式和脚本即时可见） |
| 重新构建 | `cd solar-system` 然后 `node tools/build.mjs` |
| 回归测试 | `cd solar-system` 然后 `node tools/qa.mjs`（需要本机 Chrome 或 Edge） |

环境：Node.js 18+（构建与 QA）；浏览器需支持 **WebGL2**（Chrome/Edge 88+、Firefox 100+、Safari 15+）。
WebGL2 不可用时会显示一张可读的降级说明页，不会黑屏。

- **点击容差**：天体在屏幕上很小时（全景里通常只有 3–4 px），命中半径留 ≥ 12 CSS px，
  鼠标悬停时画面里会出现一圈青色高亮环，左下角读数会显示它的日心距与地心距。
- **状态可分享**：`#body=jupiter&date=2026-11-04&scale=orrery` 写进地址栏，刷新可还原。

- **可访问性**：Canvas 有 `aria-label` 与文字版天体列表；所有按钮可 Tab；焦点可见；
  浮层打开时锁定背景滚动，关闭后焦点归还触发元素。

这是本页最该被检查的一张表。

### 真的（有代码、可验证）

| 项目 | 做法 / 出处 |
| --- | --- |
| 行星与太阳的位置 | JPL「Approximate Positions of the Planets」Table 1 根数，牛顿迭代解开普勒方程（tol 1e-6°），`Rz(−Ω)·Rx(−I)·Rz(−ω)` 转到 J2000 黄道 |
| 轨道形状与倾角 | 同一套根数采样真实椭圆（半长轴、偏心率、倾角都参与），不是画圆，也不在同一平面 |
| 公转周期 | 根数的平均运动反推，与 NASA 表一致（海王星除外，见「数据口径」） |
| 自转周期与方向 | NASA 表值；金星与天王星逆行 |
| 行星相对大小 | 同一模式下所有天体共用同一个半径倍率，比例是真的 |
| 土星环几何 | 换算成土星赤道半径的倍数参与光线求交：环在行星前 / 后、卡西尼缝、行星投在环上的影子都是算出来的 |
| 天王星环 | 同上，13 条暗环按真实半径压缩成 41,800–51,149 km 的窄环带 |
| 恒星位置 | HYG v4.0 星表 8,920 颗（V ≤ 6.5），J2000 赤经赤纬 → 黄道；**不是随机撒点** |
| 恒星相对亮度 | `I ∝ 10^(−0.4·m)` |
| 恒星颜色 | B−V → 近似色温 → 黑体色 |
| 银河带方向 | IAU J2000 北银极与银心定义的真实银道面 |
| 河外星系位置 / 角径 / 星等 | 逐条取自 Wikipedia infobox（2026-11-04），见 `research/SOURCES.md` |
| 轴倾角与极轴方位 | 倾角取 NASA 表，方位角由真实极轴赤经反解，见 `research/pole-directions.md` |
| 太阳本动 19.4 km/s | NASA Sun Fact Sheet 的 `Speed relative to nearby stars`，向点 RA 18h28m / Dec +30° |
| 太阳绕银心 220 km/s / 2.4 亿年 / 8.3 kpc | Wikipedia: Milky Way；里程表按 `v/R` 算角速度，与 2.4 亿年自洽 |
| 相对 CMB 369.82 km/s | Planck 2018（经 Wikipedia 转述），含 ±0.11 的不确定度 |
| L2 恒星的真实距离 | HYG v4.0 的 `dist` 字段，25 pc 内 1,503 颗；**不含自行**，位移全部来自太阳 |

### 艺术的（必须标注）

| 项目 | 说明 |
| --- | --- |
| 所有表面纹理 | fBm / 脊状 / 胞状噪声生成的水星撞击坑、木星条带、火星峡谷，形似而非实测 |
| 所有颜色 | 按真实色调近似，不做光谱还原 |
| 银河的云气与尘埃带细节 | 方向是真的，形态是画的 |
| 星系的旋臂、团块、伴星系光点 | M31 的 M32/M110 只是示意亮点 |
| 星芒、衍射十字 | 只给最亮的几颗，纯装饰 |
| 太阳的日冕、针状体、耀斑形态 | 真实日冕比光球暗 6 个量级，画面里无法等比，压缩到 1–2 个太阳半径内可见 |
| 地球夜面灯光 | 真实夜光分布不在本页数据范围内，只有示意 |
| 卫星轨道 | 月球、木卫一至四、土卫六、火卫一/二：相位按周期推算，**不是星历**；月球轨道半径压缩到 12 个地球半径以便看见 |
| 光照强度补偿 | 真实 1/r² 会让海王星只剩地球的 0.1%，画面里做了压缩（`1.15/r^0.55`，夹在 0.55–1.12） |
| 轨迹放大因子 | 太阳漂移按 1/N 显示（默认 ×20），让螺距与轨道直径可比；读数仍按真实值 |
| L3 银河视图 | 独立的 kpc 示意坐标系，用淡入淡出过渡，不是与太阳系同一套比例 |
| 银河尺度运动 | 匀速圆轨道近似：真实轨道有径向振荡、会穿旋臂、银心距缓慢变化，都不模拟 |

页面上每一处「示意」都有统一角标（信息面板底部那行锈橙色小字）。

## 五、尺度模式与失真

三种模式共用一套几何，只在「距离怎么映射」和「半径乘多大」上不同。
切换后右侧控制台会实时显示当前失真程度。

| 模式 | 距离 | 天体半径 | 失真标注 |
| --- | --- | --- | --- |
| `orrery`（默认） | `D = 1.15 · r^0.55` | ×36 | `距离 r^0.55 压缩 ×0.25 · 半径 ×36 · 最小 3.2 px` |
| `distance` | `D = 1.0 · r`（线性真实） | ×30 | `距离线性 ×1.00 · 半径 ×30 · 最小 2.6 px` |
| `true` | `D = 1.0 · r`（线性真实） | ×1（线性真实） | `距离与半径均为线性真实值 · 无最小像素保护` |

切到 `true` 时，画面底部会直接给出一条提示，数字是**按当前机位实时算出来的**：
「这一机位下：太阳半径 0.062 像素，地球半径 0.0006 像素」。

**`true` 模式下是真的什么都没放大。** 太阳半径 0.004651 AU，在装得下海王星轨道的机位里
只占 **0.06 像素**；地球半径 4.26×10⁻⁵ AU，占 **0.0006 像素**。所以在那个机位里，
画面里只剩轨道线与一颗极小的太阳——这正是要让人理解的事，没有用「自动放大」把它藏起来。
（亚像素天体不参与绘制，否则浮点误差会画出噪点；点击容差仍然保留 12 px。）

### 必须写明的三个口径

1. **地球位置是地月质心。** JPL 那一行是 `EM Bary` = Earth/Moon Barycenter，不是地球本身，
   最大偏差约 4,700 km（地月距离约 384,400 km）。页面上照用，README 与数据来源里都写清楚。
2. **轨道根数的拟合区间是 1800–2050，页面上不做冻结。** 时间可以一直走下去，越过 2050 之后是外推
   （根数线性外推 + 开普勒方程照解），行星仍然在动、没有停摆。日期控件接受 1600–2400；
   再往外（比如 1 亿年/秒 跑几分钟）就是更远的外推，位置只剩「还在转」的意义，不能当天文历表用。
3. **卫星数是会变的。** 2025 年 3 月口径：木星 95、土星 274。界面一律标
   「截至 2025 年 3 月」，不写「目前」。

### 另外两个诚实记录

- **海王星公转周期**：NASA 表写 59,800 天，而由 JPL 根数的平均运动反推是 **60,190 天**（≈164.8 年，
  与天文年历一致）。两处口径不同，页面显示 NASA 表值，`tools/astro-check.mjs` 同时断言这两个数字。
- **「倾角」不是相对黄道的倾角**：NASA 表的 Obliquity to Orbit 是相对**轨道法线**的倾角。
  把极轴换算到黄道系时，行星自身轨道倾角（最大 7°）会让「相对黄道的倾角」略有不同——
  例如水星相对轨道法线是 0.034°，相对黄道法线是 4.36°。两个数都写在 `data.bodies.js` 里，
  渲染用后者（环面朝向才和真实极轴一致）。
- **天王星 2026 年看起来是「正面朝向我们」**：它的极轴赤经 257.311°，2026 年前后正接近极向太阳
  （下一次至点约在 2028 年），所以环在画面里接近正圆而不是细线。这是算出来的结果，不是画错。

**渲染方式**：没有 Three.js。一个全屏三角形，逐像素解一串球体求交（太阳 + 八大行星 + 八颗卫星 + 两个环面），
得到 HDR 颜色与自定义深度；星点走独立的点精灵通道（用同一深度做遮挡）、轨道线与螺旋轨迹走 CPU 侧近平面裁剪，
最后经过「亮部提取 → 两级可分离高斯 → ACES → 色差 / 暗角 / 颗粒」。
因为不依赖深度缓冲排序，6×10⁻⁴ AU 到 30 AU 可以同时出现在一帧里。

**细节是真的会变多**：特写时 `uDetail` 由「相机距离 / 天体半径」决定，它直接控制 fBm 的层数
（3 层 → 8 层）与多层撞击坑的开启阈值。不是把同一张图放大。

**LOD 是连续的**：`uNearMix`（L2 恒星邻域）与 `uGalaxyMix`（L3 银河视图）都由相机距离的对数插值算出，
跨档只有淡入淡出，没有黑屏也没有跳变。L3 是独立的 kpc 坐标系，界面上标了「示意比例」。

**确定性截图接口**：
`index.html?shot=1&focus=jupiter&date=2026-11-04&scale=orrery&ui=0&dpr=1&frame=galactic&zoom=1`
冻结时间、固定机位、固定帧号、曝光直接到位，渲染 6 帧后置 `data-ready="true"`。
同一地址两次截图 sha256 一致（QA 会验）。

**镜头取景是按 FOV 算的，不是写死的倍数**：点击天体时用
`dist = R / sin(min(竖向半视角, 横向半视角) × 0.64)` 求出「圆面占视口 64%」的距离，
带环的按环外缘算；双击给 0.92 的最近距离，滚轮下限 0.985 —— 所以任何画面比例下都不会出现
「贴到云层上、只剩一片」或者「行星被切掉」的情况。竖屏手机上特写会把天体往上抬 30%，
并且把控制台移出画面，不让抽屉和图例压住它。

**性能**：DPR 上限 2，场景缓冲像素预算 1.4M / 3.0M / 5.2M 三档（标准 / 高 / 电影级），窄屏自动用标准档；
标签页隐藏时 `requestAnimationFrame` 自然停摆。

**超采样抗锯齿**：场景在 `1.0 / 1.25 / 1.5` 倍分辨率上渲染，合成时每个输出像素做 4 抽样 box 降采样，
行星边缘、环的细缝、土星环阴影的锯齿会明显少一截；输出前还有一层 1.6/255 的抖动，压掉暗部渐变的色带。

**仪器面板**：顶部是实时遥测（FPS / 帧号 / 画质 / 渲染分辨率 ×超采样 / LOD / DPR）；
「观测设置」展开后有画质、星空亮度、曝光、辉光、颗粒、色差六个滑杆，
调试视图可以切到 `成片 / 场景 / 辉光 / 无辉光` 四种输出，「存图 PNG」把当前帧存成文件，「复位」一键还原。

### v2 里刻意没做的事（宁缺毋滥）

- **没有引入 three.js**：整页是自己写的 WebGL2 光线求交渲染器，场景、相机、星点、线段、后期都是自己的管线；
  螺旋轨迹用的是已有的线段通道，换 three.js 既不会更好看，还会把「单文件、零依赖、双击可开」这条丢掉。
  想加的是镜头语言而不是渲染框架，所以只改了相机的行为（留在参考系里 + 死区跟随）。
- **没给 L2 的恒星编自行**：星表里没有可靠自行数据，所以只移动太阳，恒星位置是 J2000 静态值。
- **没把 L3 画成连续缩放**：银河是独立坐标系，用淡入淡出过渡，界面上写明「示意比例」。
- **没让银河尺度运动参与行星定位**：行星仍走 JPL 根数，2050 之后是外推而不是「日心坐标 + 银河位移」拼出来的。
- **没把轨迹放大因子藏起来**：它出现在控件、里程表和对照插图三处，并写明真实螺距 46.4 AU/年。

# HELIOS · 太阳系观测台

> 把 45 亿公里折进一屏，还能点开其中任何一颗。

一个**单页、零依赖、可离线打开**的交互式太阳系。太阳与八大行星都能点进去——
点谁，镜头就在 1 秒内飞到谁面前，滚轮继续推近，表面细节随缩放层级真的多算几层。

**直接双击 `index.html` 就能看。** 不需要服务器、不需要联网、不需要安装任何东西。

---

## 一、它是什么

```
HELIOS · SOLAR SYSTEM OBSERVATORY
太阳系观测台
八颗行星按真实轨道运行，太阳在中心燃烧。点开任何一颗，走进去看。
```

三条承诺，缺一条都不算完成：

1. **位置是算出来的** —— 任一日期下，行星的位置来自 JPL 轨道根数 + 开普勒方程解出的真实椭圆，
   不是摆上去的装饰。改日期，位置真的会变。
2. **表面是画出来的** —— 没有一张贴图、没有素材图、没有视频。每一颗的表面都由
   fBm / 脊状噪声 / 极坐标几何在着色器里逐像素生成。
3. **九颗都能点开** —— 太阳 + 八大行星，点击 → 镜头飞行 → 特写 → 细节可再放大 → 一键返回。

**它不是**：九张详情卡片、一个贴了球贴图的轮播、或者一张会转的太阳系示意图。

## 二、怎么开

| 方式 | 做法 |
| --- | --- |
| 直接看 | 双击 `index.html`（`file://` 可开，控制台无报错） |
| 开发 | 打开 `dev.html`（外链 `src/`，改样式和脚本即时可见） |
| 重新构建 | `cd solar-system` 然后 `node tools/build.mjs` |
| 回归测试 | `cd solar-system` 然后 `node tools/qa.mjs`（需要本机 Chrome 或 Edge） |

环境：Node.js 18+（构建与 QA）；浏览器需支持 **WebGL2**（Chrome/Edge 88+、Firefox 100+、Safari 15+）。
WebGL2 不可用时会显示一张可读的降级说明页，不会黑屏。

## 三、交互一览

| 操作 | 行为 |
| --- | --- |
| 拖拽 | 环绕相机，仰角限制 ±80° |
| 滚轮 / 双指 | 对数缩放，全景 → 特写连续过渡 |
| 单击天体 | 进入该天体特写（镜头 1.0 秒缓动推进） |
| 双击天体 | 直接推到最近观察距离 |
| 特写内拖拽 | 绕着这颗天体转，看背面 |
| `1`–`9` | 直接选中：1 太阳、2 水星 …… 9 海王星 |
| `←` `→` | 在九颗天体间切换 |
| `Tab` / `Enter` | 遍历左下角天体列表并进入特写 |
| `空格` | 播放 / 暂停时间 |
| `S` | 循环切换尺度模式 |
| `B` | 开关背景（星空 / 银河 / 星系） |
| `H` | 显隐 HUD |
| `?` | 帮助浮层 |
| `Esc` | 返回全景，或关闭浮层 |

- **点击容差**：天体在屏幕上很小时（全景里通常只有 3–4 px），命中半径留 ≥ 12 CSS px，
  鼠标悬停时画面里会出现一圈青色高亮环，左下角读数会显示它的日心距与地心距。
- **状态可分享**：`#body=jupiter&date=2026-11-04&scale=orrery` 写进地址栏，刷新可还原。
- **移动端**：单指拖拽、双指缩放、点击选中；信息面板变成底部抽屉；390 px 宽无横向滚动。
- **`prefers-reduced-motion`**：不做自动运镜、不自动播放，直接停在静态全景。
- **可访问性**：Canvas 有 `aria-label` 与文字版天体列表；所有按钮可 Tab；焦点可见；
  浮层打开时锁定背景滚动，关闭后焦点归还触发元素。

## 四、什么必须真算，什么只能是艺术

这是本页最该被检查的一张表。

### 真的（有代码、可验证）

| 项目 | 做法 / 出处 |
| --- | --- |
| 行星与太阳的位置 | JPL「Approximate Positions of the Planets」Table 1 根数，牛顿迭代解开普勒方程（tol 1e-6°），`Rz(−Ω)·Rx(−I)·Rz(−ω)` 转到 J2000 黄道 |
| 轨道形状与倾角 | 同一套根数采样真实椭圆（半长轴、偏心率、倾角都参与），不是画圆，也不在同一平面 |
| 公转周期 | 根数的平均运动反推，与 NASA 表一致（海王星除外，见「数据口径」） |
| 自转周期与方向 | NASA 表值；金星与天王星逆行 |
| 行星相对大小 | 同一模式下所有天体共用同一个半径倍率，比例是真的 |
| 土星环几何 | 换算成土星赤道半径的倍数参与光线求交：环在行星前 / 后、卡西尼缝、行星投在环上的影子都是算出来的 |
| 天王星环 | 同上，13 条暗环按真实半径压缩成 41,800–51,149 km 的窄环带 |
| 恒星位置 | HYG v4.0 星表 8,920 颗（V ≤ 6.5），J2000 赤经赤纬 → 黄道；**不是随机撒点** |
| 恒星相对亮度 | `I ∝ 10^(−0.4·m)` |
| 恒星颜色 | B−V → 近似色温 → 黑体色 |
| 银河带方向 | IAU J2000 北银极与银心定义的真实银道面 |
| 河外星系位置 / 角径 / 星等 | 逐条取自 Wikipedia infobox（2026-11-04），见 `research/SOURCES.md` |
| 轴倾角与极轴方位 | 倾角取 NASA 表，方位角由真实极轴赤经反解，见 `research/pole-directions.md` |

### 艺术的（必须标注）

| 项目 | 说明 |
| --- | --- |
| 所有表面纹理 | fBm / 脊状 / 胞状噪声生成的水星撞击坑、木星条带、火星峡谷，形似而非实测 |
| 所有颜色 | 按真实色调近似，不做光谱还原 |
| 银河的云气与尘埃带细节 | 方向是真的，形态是画的 |
| 星系的旋臂、团块、伴星系光点 | M31 的 M32/M110 只是示意亮点 |
| 星芒、衍射十字 | 只给最亮的几颗，纯装饰 |
| 太阳的日冕、针状体、耀斑形态 | 真实日冕比光球暗 6 个量级，画面里无法等比，压缩到 1–2 个太阳半径内可见 |
| 地球夜面灯光 | 真实夜光分布不在本页数据范围内，只有示意 |
| 卫星轨道 | 月球、木卫一至四、土卫六、火卫一/二：相位按周期推算，**不是星历**；月球轨道半径压缩到 12 个地球半径以便看见 |
| 光照强度补偿 | 真实 1/r² 会让海王星只剩地球的 0.1%，画面里做了压缩（`1.15/r^0.55`，夹在 0.55–1.45） |

页面上每一处「示意」都有统一角标（信息面板底部那行锈橙色小字）。

## 五、尺度模式与失真

三种模式共用一套几何，只在「距离怎么映射」和「半径乘多大」上不同。
切换后右侧控制台会实时显示当前失真程度。

| 模式 | 距离 | 天体半径 | 失真标注 |
| --- | --- | --- | --- |
| `orrery`（默认） | `D = 1.15 · r^0.55` | ×36 | `距离 r^0.55 压缩 ×0.25 · 半径 ×36 · 最小 3.2 px` |
| `distance` | `D = 1.0 · r`（线性真实） | ×30 | `距离线性 ×1.00 · 半径 ×30 · 最小 2.6 px` |
| `true` | `D = 1.0 · r`（线性真实） | ×1（线性真实） | `距离与半径均为线性真实值 · 无最小像素保护` |

切到 `true` 时，画面底部会直接给出一条提示，数字是**按当前机位实时算出来的**：
「这一机位下：太阳半径 0.062 像素，地球半径 0.0006 像素」。

**`true` 模式下是真的什么都没放大。** 太阳半径 0.004651 AU，在装得下海王星轨道的机位里
只占 **0.06 像素**；地球半径 4.26×10⁻⁵ AU，占 **0.0006 像素**。所以在那个机位里，
画面里只剩轨道线与一颗极小的太阳——这正是要让人理解的事，没有用「自动放大」把它藏起来。
（亚像素天体不参与绘制，否则浮点误差会画出噪点；点击容差仍然保留 12 px。）

### 必须写明的三个口径

1. **地球位置是地月质心。** JPL 那一行是 `EM Bary` = Earth/Moon Barycenter，不是地球本身，
   最大偏差约 4,700 km（地月距离约 384,400 km）。页面上照用，README 与数据来源里都写清楚。
2. **轨道根数只在 1800–2050 有效。** 日期控件 `min="1800-01-01" max="2050-12-31"`，
   超出范围直接被拒，不做外推。
3. **卫星数是会变的。** 2025 年 3 月口径：木星 95、土星 274。界面一律标
   「截至 2025 年 3 月」，不写「目前」。

### 另外两个诚实记录

- **海王星公转周期**：NASA 表写 59,800 天，而由 JPL 根数的平均运动反推是 **60,190 天**（≈164.8 年，
  与天文年历一致）。两处口径不同，页面显示 NASA 表值，`tools/astro-check.mjs` 同时断言这两个数字。
- **「倾角」不是相对黄道的倾角**：NASA 表的 Obliquity to Orbit 是相对**轨道法线**的倾角。
  把极轴换算到黄道系时，行星自身轨道倾角（最大 7°）会让「相对黄道的倾角」略有不同——
  例如水星相对轨道法线是 0.034°，相对黄道法线是 4.36°。两个数都写在 `data.bodies.js` 里，
  渲染用后者（环面朝向才和真实极轴一致）。
- **天王星 2026 年看起来是「正面朝向我们」**：它的极轴赤经 257.311°，2026 年前后正接近极向太阳
  （下一次至点约在 2028 年），所以环在画面里接近正圆而不是细线。这是算出来的结果，不是画错。

### 星表许可

HYG Database v4.0，**CC BY-SA 4.0**，仅内联 `RA / Dec / Vmag / B−V` 四个字段，
截断星等 6.50，8,920 颗，编码后 95 KB。本页对它的衍生编码沿同一许可，署名 astronexus 贡献者。

## 七、天文计算怎么验的

```powershell
cd solar-system
node tools/astro-check.mjs        # 25 项离线断言
node tools/compare-horizons.mjs   # 联网，与 JPL Horizons DE441 对比（一次性核对）
```

`astro-check` 断言的内容包括：儒略日往返、**2026 年春分时地球日心黄经 = 180°（扣岁差）**、
地球近日点 / 远日点距离、八颗行星的公转周期、水星偏心率与倾角、倾角极差 > 6°（＝不在同一平面）、
银心必须落在银经 0°、北天极黄纬 = 90° − 23.43928°。

与 Horizons 的对比（2026-11-04 00:00 UTC，DE441）：

| 天体 | Δ黄经（″） | Δ黄纬（″） | Δ距离（km） |
| --- | --- | --- | --- |
| 水星 | −20.9 | −2.5 | 838 |
| 金星 | −1.8 | −0.5 | −208 |
| 地球 | −2.2 | 0.9 | −4,889 |
| 火星 | −14.5 | −0.1 | −12,789 |
| 木星 | 84.6 | 1.5 | −336,396 |
| 土星 | 265.8 | 1.1 | 56,177 |
| 天王星 | 0.4 | 0.0 | −791,282 |
| 海王星 | −31.7 | 0.6 | −67,909 |

全部落在 JPL 原文给出的 1800–2050 名义误差范围内（那张表本身就允许木星 400″、土星 600″ 的黄经误差）。
完整记录见 [`research/position-verification.md`](research/position-verification.md)。

## 八、工程结构

```
solar-system/
  index.html          构建产物，禁止手改
  dev.html            开发入口
  src/
    css/              base / hud / panels
    js/
      data.bodies.js      九颗天体 + 八颗卫星 + 逐字段 source
      data.orbits.js      JPL 根数与变化率
      data.sky.js         星表元信息、银河方向、河外星系与深空天体
      data.stars.js       星表编码（生成文件，勿手改）
      astro.js            儒略日、开普勒求解、坐标旋转
      renderer.js         WebGL2 上下文、帧缓冲、星点与线段几何
      camera.js           轨道相机、缓动飞行、投影与拾取
      ui.js               HUD、面板、帮助浮层、焦点管理
      app.js              装配与状态机
      shaders/            common / surface / sky / scene / stars / post
  tools/
    build.mjs            把 dev.html + src/ 内联成单文件
    qa.mjs               无头 Chrome 冒烟 + 九颗特写 + 确定性截图 + 移动端
    astro-check.mjs      天文核心的离线断言（25 项）
    compare-horizons.mjs 与 JPL Horizons 对比（联网，一次性）
    fetch-stars.mjs      抓 HYG 星表并编码
    fetch-moons.mjs      抓卫星半径与轨道
    derive-poles.mjs     由真实极轴赤经反解倾斜与方位
    smoke.mjs            一帧冒烟，输出截图与控制台
  research/           数据源与核对记录
  qa/report.json      验收报告
```

**渲染方式**：没有 Three.js。一个全屏三角形，逐像素解一串球体求交（太阳 + 八大行星 + 八颗卫星 + 两个环面），
得到 HDR 颜色与自定义深度；星点走独立的点精灵通道（用同一深度做遮挡）、轨道线走 CPU 侧近平面裁剪，
最后经过「亮部提取 → 可分离高斯 → ACES 合成」。因为不依赖深度缓冲排序，6×10⁻⁴ AU 到 30 AU 可以同时出现在一帧里。

**细节是真的会变多**：特写时 `uDetail` 由「相机距离 / 天体半径」决定，它直接控制 fBm 的层数
（3 层 → 8 层）与多层撞击坑的开启阈值。不是把同一张图放大。

**确定性截图接口**：
`index.html?shot=1&focus=jupiter&date=2026-11-04&scale=orrery&ui=0&dpr=1`
冻结时间、固定机位、固定帧号，渲染 6 帧后置 `data-ready="true"`。同一地址两次截图 sha256 一致（QA 会验）。

**性能**：DPR 上限 2，像素预算 1.15M / 2.2M / 3.6M 三档（标准 / 高 / 电影级），窄屏自动用标准档；
标签页隐藏时 `requestAnimationFrame` 自然停摆。

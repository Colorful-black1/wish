# 任务：打造「HELIOS / 太阳系观测台」——太阳与八大行星都能点进去的实时太阳系

你现在是一名实时图形工程师、天文数据校对员，也是一个懂得克制的界面设计师。

请做一个**单页、零依赖、可离线打开**的交互式太阳系：

> 一台可以用鼠标走进去的太阳系仪。太阳和八大行星，点谁，镜头就飞到谁面前。

参考作品是 [`GARGANTUA / 卡冈图雅`](https://120403.xyz/wishcraft/projects/gargantua/)（[README](https://github.com/MY-Final/wishcraft/tree/main/projects/gargantua)）：它立下了三条标准 —— **画面由方程算出来、数据有出处、结果可验收**。这一页要继承这三条，但对象从黑洞换成太阳系，而且多一个明确要求：

**太阳和八大行星全部可点击，点击后镜头推进到特写，可以继续放大查看细节。**

## 二、这个页面是什么

一句话：**把 45 亿公里折进一屏，还能点开其中任何一颗。**

三条承诺，缺一条就不算完成：

1. **位置是算出来的** —— 任一日期下，行星按真实轨道根数解出来的位置，不是摆上去的装饰。
2. **表面是画出来的** —— 没有贴图、没有素材图、没有视频；每一颗的表面由程序化噪声与几何生成。
3. **九颗都能点开** —— 太阳 + 八大行星，点击 → 镜头飞行 → 特写 → 细节可再放大 → 一键返回。

**它不是**：九张详情卡片、一个贴了球贴图的轮播、或者一张会转的太阳系示意图。

交互硬要求：

- **点击命中**：鼠标与触摸都能点中；天体在屏幕上很小时，命中半径留 **≥ 12 CSS px** 的容差，并显示悬停高亮环。
- **键盘**：`1`–`9` 直达九颗天体；`Tab` 可遍历 HUD 里的天体列表，`Enter` 进入特写。

- **状态可分享**：当前聚焦天体、日期、尺度模式写进 URL（如 `#body=jupiter&date=2026-11-04&scale=orrery`），刷新可还原。

## 五、天文计算（这一段决定作品的可信度）

严格按 `research/jpl-approx-positions.md` 的步骤实现：

1. `T = (JD − 2451545.0) / 36525`；日期用 UTC，控件范围 1800–2050。
2. 根数按 `a = a₀ + ȧT` 等线性外推；`ω = ϖ − Ω`，`M = L − ϖ`。
3. `M` 归一到 `[−180°, 180°]`，用牛顿迭代解 `M = E − e* sin E`（`e* = 180/π · e`），迭代到 `|ΔE| ≤ 1e-6°`。
4. `x' = a(cos E − e)`，`y' = a√(1 − e²) sin E`，再按 `Rz(−Ω)·Rx(−I)·Rz(−ω)` 转到黄道坐标。
5. 轨道线由同一套根数**采样真实椭圆**得到，不是画圆；倾角 `I` 必须参与，侧视时能看出行星不在同一平面。

必须做到的细节：

- 自转用真实周期，**金星与天王星是逆行**（周期为负），不能一律逆时针。
- 地球用 EM 质心代替，界面上标一句「地球位置为地月质心近似」。
- 行星位置随日期实时更新；改日期后位置必须真的变（验收会截图对比）。
- 太阳的半径、行星的半径都按 `research/SOURCES.md` 的数值等比缩放，**行星之间的相对大小必须是真的**。

## 六、背景：星空、银河与其他星系（不许贴图）

先把一件事说清楚：**站在太阳系里看出去，能看见的「其他星系」是星系本身，不是别的星系的单颗恒星** —— 仙女座星系里最亮的单颗恒星视星等也在 15 等以外，肉眼（极限约 6.5 等）根本看不见。所以背景分三层，真假分明。

### 1. 恒星层：真实星表，不是随机撒点

- 数据二选一：**Yale BSC5**（约 9,100 颗，到 6.5 等，含 J2000 赤经/赤纬、V 星等、B−V 色指数）或 **HYG v3**（`codeberg.org/astronexus/hyg`）。构建时截取并内联；星表名称、版本、截断星等、许可写进 `research/SOURCES.md` 与 `README.md`。
- 位置：J2000 赤道坐标 → 黄道坐标（本页场景是黄道系），放在天球无穷远处。**只随相机朝向旋转，不随模拟日期变化** —— 周年视差只有角秒级，不要伪造。
- 亮度：按星等换算相对通量（`I ∝ 10^(−0.4·m)`），最亮的那几颗可以加轻微星芒；**不允许"每颗星一样亮"**。
- 颜色：由 B−V 近似色温再转黑体色，蓝白到橙红的分布要看得出来。
- 若拿不到完整星表，可以退化为「最亮 N 颗」，但位置仍必须来自真实星表；**随机撒点算不合格**。
- 体积控制：星表建议用紧凑编码（定点整数 + 差分）内联，整份背景数据控制在 400 KB 量级；超了先降星等截断，不要砍掉真实坐标换成随机数。

### 2. 银河层：方向必须是真的

- 用真实银道坐标系：银北极（J2000）RA `12h51m26.28s` / Dec `+27°07′41.7″`，银心（l=0, b=0）RA `17h45m37.2s` / Dec `−28°56′10″`。银河带必须贴着这个面铺开。
- 形态用 fBm 云气 + 暗尘带：银心方向更亮更黄，反银心更暗；北半球夏天看到的那条亮带、以及被尘埃切成两半的样子要能对上。
- **禁止**把银河画成一条随机斜带 —— 它必须和猎户座、天鹅座、人马座这些方向对得上。

### 4. 视差、遮挡与曝光

- 背景在天球无穷远：相机平移不产生视差，只有朝向改变才移动。
- 行星与太阳会遮挡背景；太阳特写时背景被强光压掉是正常的，不要为了"看见星星"去降低太阳亮度。
- `B` 键开关背景；关掉后行星渲染不受影响。
- 给一个「星空亮度」参数，让银河暗部与太阳高光能共存（HDR + tonemap 要兼顾，不能二选一）。

## 七、尺度模式（必须做三种，并把失真说清楚）

| 模式 | 距离 | 天体大小 | 用途 |
| --- | --- | --- | --- |
| `orrery`（默认） | 径向压缩（如 `r^0.5` 或分段压缩） | 放大到可见 | 看清整体结构 |
| `distance` | 线性真实距离 | 最小像素保护 | 感受距离差异 |
| `true` | 线性真实距离 | 线性真实半径 | 展示「真实比例下行星只有几个像素」 |

三种模式都要在界面上标注**当前失真程度**（例如「距离压缩 ×0.42」），并允许一键切换。切换到 `true` 时给一条明确的提示：真实比例下，地球在这个尺度里不到 1 像素 —— 这正是要让人理解的事，不要用「自动放大」把它藏起来。

## 八、渲染：什么必须真算，什么只能是艺术

**必须真算（有代码、可验证）**

- 轨道位置、轨道形状、倾角、公转周期
- 自转周期与方向
- 行星相对大小、距离比例
- 土星环的几何平面与遮挡关系（环在行星前 / 后 / 侧面）
- 日食式的光影关系（可选，但做就要正确）
- 当前日期对应的行星位置（日期变化 → 位置变化）
- 恒星的天球位置与相对亮度（来自真实星表，按星等换算）
- 银河带与银极、银心的对齐关系
- 河外星系与深空天体的天球位置、角径、星等

**只能是艺术化（必须标注）**

- 表面纹理：fBm 噪声、陨坑分布、条带形状 —— 参考真实地貌特征，但**不是观测数据**
- 颜色：按真实色调近似，不做光谱还原
- 银河的云气形态与尘埃带细节（方向真实，形状艺术化）
- 星系的形态细节（旋臂、团块），以及 M32/M110 这类伴星系的小光点
- 星点的闪烁、星芒、衍射十字
- 太阳的日冕、耀斑形态
- 地球夜面灯光（真实夜景分布不在数据范围内，只能示意）
- 卫星：只画主要卫星（月球、木卫一至四、土卫六、火卫一/二），轨道位置示意

页面每处「示意」都要有统一角标，`README.md` 里放一张「什么是真的，什么是艺术」的总表 —— 这是参考作品最值得继承的部分。

## 九、视觉方向

**天文台仪器**，不是科幻飞船：

- 底色近黑（`#05070A` 一类），主文字米白（`#EDE6D6`），太阳用暖金（`#E8B04B`），轨道线用低饱和青（`#6FA8B8`），警示用锈橙（`#D9603B`）。
- 细线、小号等宽字、大量留白；数字用等宽，标题用系统衬线。
- HUD 贴在画面四角，中间永远留给天体；特写时右侧浮出信息面板（移动端变底部抽屉）。
- 动效只做「有信息量」的：镜头飞行、行星自转、时间推进；不做呼吸光、不做满屏粒子。
- 明确避开：紫色渐变星云、发光描边卡片、每个天体配一个 emoji、把 HUD 做成仪表盘堆叠。

**首屏文案（可直接用）**

- 眉标：`HELIOS · SOLAR SYSTEM OBSERVATORY`
- 主标题：**太阳系观测台**
- 副标题：八颗行星按真实轨道运行，太阳在中心燃烧。点开任何一颗，走进去看。
- 操作提示：`点击天体进入特写 · 拖拽旋转 · 滚轮缩放 · Esc 返回`

**信息面板（特写时）** 至少包含：名称（中/英）、类型、直径、质量、表面重力、自转周期、公转周期、平均距日、平均温度、卫星数，以及一条「与地球对比」的直径比例条。每个数字在数据文件里带 `source` 字段。

硬性技术约束：

1. **零外部请求**：不引 CDN、不引网络字体、不引远程图片、不放视频。星空、行星表面、太阳全部程序化生成。
2. **不引入 three.js**：本仓库要求单文件可开，而 three.js 需要多文件 ES Modules；请直接写 WebGL2（一个全屏 quad + 若干 shader pass 足够）。若确实需要库，必须内联进产物并附 MIT 许可说明。
3. **数据与渲染分离**：所有数字在 `data.*.js`，渲染代码不出现裸数字；每个数值带 `source`。
4. **确定性截图接口**：`?shot=1&focus=jupiter&date=2026-11-04&scale=orrery&ui=0&dpr=1` 冻结时间与机位，渲染若干帧后置 `data-ready="true"`；同一 URL 两次截图应像素一致（sha256 相同）。
5. **性能**：DPR 上限 2，像素预算上限（如 2.2M），三档质量 Standard / High / Cinematic；移动端自动降档；隐藏标签页暂停渲染。
6. **降级**：WebGL2 不可用时显示可读的说明页（列出浏览器要求），不能黑屏。
7. 构建脚本用 `process.cwd()`，必须在 `solar-system/` 内执行。

## 十三、禁止项

- 禁止用贴图、素材图、视频、GIF 或截图冒充行星表面与太阳活动。
- 禁止用星空照片、全景星图贴图冒充星表 —— 星星的位置必须来自真实数据的投影。
- 禁止随机撒点当星空；禁止把银河画成与真实银道面无关的斜带。
- 禁止给河外星系画"成片的单颗恒星"来暗示能看见别的星系的星星（物理上不可分辨）。
- 禁止画正圆周转轨道，禁止把行星都画在同一平面。
- 禁止编造数据；没有来源的字段写「暂无可靠数据」。
- 禁止把艺术化颜色说成「真实颜色」，把示意卫星位置说成「实时位置」。

- 禁止出现假按钮、假开关、点了没反应的列表项。
- 禁止满屏辉光、紫色星云、卡片堆叠式的「AI 味」设计。

## 十四、执行顺序

1. 先写 `astro.js`：儒略日 → 根数 → 开普勒 → 坐标，跑通 8 颗行星在某一天的坐标，并与 `research/SOURCES.md` 的常识值对一遍（例如地球 1 月初在近日点附近）。
2. 搭 `dev.html` + 空 shader，把 9 个点按坐标画出来，确认轨道形状与倾角看着对。
3. 实现相机飞行与点击拾取 —— **先把「点开再返回」这条主路径打通**，这是本愿望的核心。
4. 铺背景：星表投影 → 银河带 → 河外星系。用猎户座腰带、北斗七星、仙女座方向自查一遍；背景定不下来，后面调色调会把方向感彻底带偏。
5. 逐个补天体表面 shader：先太阳与地球，再气态巨行星，最后土星环。
6. 补 HUD、时间控制、尺度模式、URL 与持久化。
7. 收尾：质量档、移动端、reduced-motion、降级页、README 与验收记录。

# 任务：打造一个顶级的《奥特曼宇宙编年史》交互式 HTML 网站

你现在是一名世界顶级的 Web 视觉设计师、前端工程师、科幻世界观研究者和数字博物馆策展人。

请以“奥特曼宇宙数字博物馆（ULTRAMAN UNIVERSE ARCHIVE）”为主题，为我生成一个视觉效果惊艳、内容丰富、交互流畅、具有电影级质感的 HTML 网站。

这不是一个普通的奥特曼介绍页面，而是一个能够系统展示奥特曼系列现实发展史，以及奥特宇宙内部历史与重大事件的沉浸式数字档案馆。

**核心目标：让访问者仿佛进入了光之国的宇宙档案中心，探索奥特曼系列数十年的发展历程，以及 TV、电影和剧场版作品中宏大的宇宙历史。**

------

## 一、整体设计理念

### 1. 视觉风格

采用“科幻电影界面 + 宇宙档案馆 + 高级数字博物馆”的设计方向。

整体风格要求：

- 深空黑、午夜蓝作为基础背景色。
- 使用奥特曼标志性的银色、红色、蓝色、金色作为辅助色。
- 使用星云、星河、宇宙尘埃、光粒子、能量波纹、星际坐标等视觉元素。
- 重点区域可以采用玻璃拟态、半透明面板、精细边框、柔和光晕和金属质感。
- 页面具有明显的空间纵深感，避免所有内容都像普通后台管理系统一样平铺。
- 重要作品、角色和历史事件应具有独特的视觉识别。
- 适当加入光效、渐变、微动画、悬浮效果和滚动触发动画。
- 设计必须有明确的视觉层级，避免过度炫光、满屏渐变、字体过小和信息堆积。

整体气质参考高品质科幻电影的片头、未来文明的数据库界面以及高端数字展览网站。

### 2. 页面体验

- 首屏必须具有强烈的视觉冲击力。
- 标题、时间、数据和重点事件应具有仪式感。
- 时间轴需要有清晰的年代感与历史纵深。
- 用户可以通过点击、筛选、搜索等方式探索不同年代和不同宇宙事件。
- 每个重要角色、作品和历史事件都应具有详细的信息展示。
- 页面需要兼顾桌面端和移动端。
- 所有交互必须真实可用，不允许仅绘制外观却没有功能的按钮。

------

## 二、网站整体结构

采用单页应用式体验，使用顶部导航、分区滚动和交互式内容面板。

网站名称：

**ULTRAMAN UNIVERSE ARCHIVE**

中文名称：

**奥特曼宇宙编年史**

副标题：

“从光之国的诞生，到跨越多元宇宙的光之传承。”

顶部导航至少包含：

1. 宇宙首页
2. 系列发展史
3. 宇宙编年史
4. 奥特战士档案
5. 宇宙文明与势力
6. 经典战役
7. 作品索引

导航应支持点击后平滑滚动到对应区域，并清晰显示当前所在栏目。

## 三、模块一：宇宙首页

设计一个极具震撼力的首屏。

### 视觉要求

- 深邃的宇宙背景。
- 中央或偏右位置呈现具有英雄感的奥特曼剪影、能量轮廓或宇宙战士视觉形象。
- 背景可以包含遥远星球、星云、光之国城市轮廓和星际光线。
- 不要让装饰元素影响文字阅读。
- 如没有合法可用的官方图片资源，可以使用自制 SVG、CSS 光效、抽象能量轮廓或可替换的图片占位资源，不要依赖不存在的图片地址。

### 首屏文字

主标题：

奥特曼宇宙编年史

英文标题：

CHRONICLES OF LIGHT

副标题：

“光并非诞生于某一个英雄，而是在无数次黑暗降临之时，被一次又一次传承。”

主要按钮：

- 开始探索
- 穿越历史

点击“开始探索”进入系列发展史。

点击“穿越历史”进入宇宙编年史。

### 宇宙数据面板

设计精致的数据统计区域，可展示：

- 系列起点：1966 年
- 跨越年代：从 1966 年至当前最新作品
- 作品档案：依据实际整理的作品数量动态统计
- 历史事件：依据实际整理的事件数量动态统计
- 宇宙档案：奥特战士、宇宙文明与经典战役的实际收录数量

所有统计数字必须根据网站内实际存在的数据生成，不能为了视觉效果随意编造。

## 四、模块二：奥特曼系列发展史

这是网站最重要的模块之一。

注意：这里展示的是**奥特曼系列在现实世界中的诞生、发展、革新与传承**，不是奥特宇宙内部的历史。

从 1966 年《奥特 Q》《奥特曼》所代表的系列起点开始，梳理到网站制作时最新能够核实的作品。

### 1. 发展史时间轴

设计一条可以横向或纵向探索的交互式时间轴。

时间轴需要按照真实发行年份排列，并为重要的系列阶段设置视觉分区。

建议重点整理以下阶段：

- 1966—1967：系列诞生与初代奥特曼时代
- 1970 年代：昭和奥特曼黄金时代
- 1980 年代：系列调整、延续与不同作品形态的探索
- 1990 年代：平成系列的重新发展与世界观探索
- 2000 年代：新世纪系列与多种叙事模式
- 2010 年代：新时代作品、经典回归与跨作品联动
- 2020 年代至今：新生代系列、电影项目、周年纪念与最新作品

以上只是初始分区建议。必须根据真实作品发行年份、制作背景和系列划分进行核实，不能机械套用分区。

### 2. 重要作品卡片

每一部重点作品应包含：

- 中文作品名称
- 日文原名或正式英文名
- 首播或上映年份
- 作品类型：TV、电影、OVA、网络剧集、特别篇等
- 主角奥特曼
- 所属系列阶段
- 一句话剧情概述
- 系列历史地位
- 创新之处或重要影响
- 关联作品
- 官方图片或可替换的视觉资源

重点收录但不限于：

《奥特 Q》《奥特曼》《赛文奥特曼》《杰克奥特曼》《艾斯奥特曼》《泰罗奥特曼》《雷欧奥特曼》《爱迪奥特曼》《迪迦奥特曼》《戴拿奥特曼》《盖亚奥特曼》《高斯奥特曼》《奈克瑟斯奥特曼》《麦克斯奥特曼》《梦比优斯奥特曼》《赛罗奥特曼》相关作品，以及《银河奥特曼》《艾克斯奥特曼》《欧布奥特曼》《捷德奥特曼》《罗布奥特曼》《泰迦奥特曼》《泽塔奥特曼》《特利迦奥特曼》《德凯奥特曼》《布莱泽奥特曼》《亚刻奥特曼》等作品。

还应根据实际情况收录后续新作品、重要剧场版、跨系列电影和具有重大历史意义的特别项目。

注意：以上列表是基础参考，不代表全部作品。需要补充重要遗漏，并正确区分 TV 主系列、电影、特别篇、衍生作品及其他作品类型。

### 3. 点击作品查看详情

用户点击任意作品卡片后，打开精致的详情面板或弹窗，展示：

- 作品海报或视觉封面
- 基本资料
- 剧情简介
- 主要角色
- 重要敌人
- 代表性战役
- 世界观设定
- 对系列发展的影响
- 与其他作品的关联

内容需要具有百科价值，不能所有作品都只有一句空洞的介绍。

### 4. 时间筛选与搜索

提供以下交互：

- 按年代筛选。
- 按昭和、平成、新生代等系列阶段筛选。
- 按 TV、电影、OVA、网络作品等类型筛选。
- 按奥特曼名称搜索。
- 按作品名称搜索。
- 点击年份快速定位时间轴。

筛选条件应可以组合使用，并支持清除筛选。

## 五、模块三：奥特宇宙内部编年史

这是整个网站最具特色的部分。

注意：**这里讲述的是奥特曼 TV、电影、剧场版等作品中虚构宇宙的历史，不是现实世界的发行历史。**

奥特曼系列存在多个世界观、平行宇宙和独立作品设定，因此不能把所有事件简单拼接成一条没有争议的绝对时间线。

### 1. 宇宙起源与文明诞生

从各作品明确提及的宇宙历史出发，整理重要的背景事件，例如：

- M78 星云光之国及其文明的发展。
- 奥特之星的历史背景。
- 光之国文明发生重大变化的历史事件。
- 等离子火花塔及其对光之国的影响。
- 奥特战士的诞生、进化与使命。
- 宇宙中其他重要文明的发展。
- 古代遗迹、远古战士和史前威胁。
- 多元宇宙及不同宇宙之间的关联。

必须区分作品中明确交代的历史、官方资料补充的设定，以及基于剧情推导的解释。

不能把粉丝猜测写成官方事实。

### 2. 宇宙历史事件时间轴

按照事件在虚构世界中发生的先后顺序，设计一条具有史诗感的宇宙历史时间轴。

建议涵盖以下主题，但需要核实其具体内容、年代和世界观归属：

**第一纪元：宇宙与古代文明**

- 宇宙起源相关设定。
- 光之国文明的早期历史。
- 古代文明、远古战士和史前威胁。
- 不同作品中涉及的古代封印与遗迹。

**第二纪元：光之国的变革**

- 等离子火花塔相关历史。
- 光之国居民成为奥特战士的相关设定。
- 奥特之父、奥特之母等重要人物的历史背景。
- 宇宙警备队的形成及其职责。

**第三纪元：宇宙危机与经典战役**

- 巴尔坦星人等重要宇宙种族引发的冲突。
- 杰顿等经典强敌带来的重大危机。
- 宇宙警备队面对的重大威胁。
- 贝利亚相关事件与光之国遭遇的危机。
- 赛罗奥特曼参与的重要宇宙事件。

**第四纪元：多元宇宙与跨宇宙事件**

- 不同宇宙之间的穿越与交汇。
- 奥特曼与其他宇宙的连接。
- 赛罗相关的多元宇宙冒险。
- 重要剧场版中的宇宙级威胁。
- 银河、维克特利、欧布等相关作品中的重要世界观事件。
- 跨作品联动与不同奥特战士之间的合作。

**第五纪元：新时代宇宙危机**

- 新时代作品中的重大宇宙威胁。
- 重要反派的行动及其影响。
- 不同奥特战士之间的传承与合作。
- 重要电影、剧场版和周年项目涉及的历史事件。
- 截至最新核实作品的后续发展。

上述分期只是网站的信息组织方式，不代表官方已经确立这些纪元名称或分界。

### 3. 每个重大事件必须包含的信息

每条宇宙历史事件至少包含：

- 事件名称
- 发生年代或相对时间
- 所属宇宙或世界观
- 关联 TV、电影或剧场版
- 主要人物
- 事件背景
- 事件经过
- 事件结果
- 对宇宙格局的影响
- 后续影响
- 官方设定依据或参考资料

对于没有明确官方年份的事件，使用“年代未明确”“发生于某事件之前”“作品未提供精确时间”等表述。

严禁为所有事件强行编造具体年份。

### 4. 事件详情与关联网络

点击重大事件后，打开详情面板。

详情面板中应展示：

- 事件发生前的宇宙局势。
- 事件的主要参与者。
- 事件的经过。
- 事件结束后的局势变化。
- 与其他事件的因果关系。
- 对应的 TV、电影或剧场版作品。
- 相关奥特战士与敌人。

如果某个事件与多个作品存在关联，可以设计关系网络或关联事件列表，让用户继续探索。

## 六、模块四：奥特战士档案

设计一个未来科技感的奥特战士数据库。

每位奥特战士应具有独立档案卡片。

### 档案信息

- 中文名称
- 日文名称
- 首次登场作品
- 首次登场年份
- 所属宇宙或世界观
- 身份与背景
- 主要能力
- 代表性技能
- 变身者
- 重要伙伴
- 主要敌人
- 经典战役
- 关联作品

优先收录具有代表性的奥特战士，包括初代、赛文、杰克、艾斯、泰罗、雷欧、爱迪、迪迦、戴拿、盖亚、梦比优斯、赛罗，以及银河、维克特利、艾克斯、欧布、捷德、泽塔、特利迦、德凯、布莱泽、亚刻等。

根据实际最新作品补充后续登场的奥特战士。

需要特别注意：

提供名称搜索、所属系列筛选和宇宙筛选功能。

## 七、模块五：宇宙文明与势力

将奥特曼世界中的重要文明、组织和敌对势力整理为独立数据库。

可以包括：

- 光之国
- 宇宙警备队
- 其他有明确设定的重要奥特文明
- 巴尔坦星人
- 雷布朗多星人相关势力
- 贝利亚相关势力
- 安培拉星人相关势力
- 黑暗路西法等相关作品中的重要威胁
- 其他具有重要剧情地位的宇宙文明与组织

具体收录范围以官方作品和资料能够核实的内容为准。

每个势力包含：

- 名称与分类
- 所属宇宙
- 文明或组织背景
- 代表人物
- 主要目标
- 与光之国的关系
- 重要冲突
- 关联作品
- 历史地位

通过不同视觉标识区分友好文明、中立势力、敌对势力及存在争议或多重立场的势力。

不要将某个反派在不同作品中的不同版本强行视为同一条连续经历。

## 八、模块六：经典战役与名场面

重点收录对奥特曼系列或相关世界观具有重大意义的战斗。

每场战役包括：

- 战役名称
- 关联作品
- 主要参战者
- 冲突背景
- 战斗经过
- 战役结果
- 对后续剧情的影响
- 相关历史事件
- 相关角色档案

可以使用横向大卡片、海报式排版和精细的视觉分层。

不要单纯堆积角色图片，要让每场战役都具有明确的历史意义和剧情上下文。

## 十一、内容准确性与资料原则

这是本项目非常重要的要求。

### 1. 现实发展史与虚构宇宙史必须严格分离

现实发展史回答：

“奥特曼系列在现实世界中什么时候诞生、推出了哪些作品、经历了哪些变化？”

虚构宇宙史回答：

“奥特曼世界中的文明如何发展、发生了哪些历史事件、不同作品之间有什么关系？”

两个模块不能混为一谈。

### 2. 作品资料必须尽可能准确

- 优先参考圆谷制作官方资料、官方网站、作品官网及官方出版物。
- 对作品名称、年份、播出顺序、上映时间、角色身份和剧情事件进行核实。
- 明确区分日本首播时间、电影上映时间、海外发行时间。
- 不确定的资料应明确标注，不得编造。
- 最新作品必须以实际能够核实的官方发布信息为准。
- 不要因为某部作品比较冷门就遗漏具有重要历史意义的作品。
- 不要把尚未播出、尚未上映或仅处于宣传阶段的项目描述成已经完整播出的作品。
- 对于平行宇宙、重启世界观、不同版本和跨系列联动，必须说明其关系，不能强行拼接。

### 3. 重要事件必须有出处

每个重大事件尽可能提供来源信息，例如：

- 官方作品名称。
- 官方作品页面。
- 对应的 TV 集数、电影或剧场版。
- 官方出版物或其他可靠资料。

如果无法找到可靠依据，应标记为“待核实”，而不是自行补齐。

### 4. 内容规模

先保证关键内容的准确性与结构完整性。

第一版至少应包含：

- 完整的发展史阶段。
- 覆盖主要年代的代表性作品。
- 重要奥特战士档案。
- 至少 20 条经过核实的宇宙历史事件。
- 至少 10 条经典战役或重大冲突。
- 多个主要宇宙文明与势力。
- 作品、角色、事件之间的关联信息。

上述数量是最低目标，不代表奥特曼系列的完整作品总量或完整历史事件总量。

如果有可靠资料支持，应继续扩展。

如果使用第三方库，必须确保依赖真实存在，且在网络可用时能够正常加载。

### 交付要求

1. 输出完整的 `index.html` 文件。
2. CSS 和 JavaScript 可以内嵌在 HTML 中。
3. 页面无需后端即可运行。
4. 作品、人物和事件的数据应与页面渲染逻辑分离，方便后续补充。
5. 尽量采用统一的数据结构和可复用的渲染函数。
6. 所有筛选、搜索、详情弹窗和导航功能必须可以实际操作。
7. 不能只生成首页，必须完成全部核心模块。
8. 不能使用大量重复的占位文字冒充真实内容。

10. 图片加载失败时应有精致的备用样式。
11. 页面需要适配常见桌面浏览器和移动设备。
12. 避免控制台报错、无效链接和失效按钮。

如果单个 HTML 文件会导致内容过长，可以在内部采用模块化的数据组织方式，但第一版仍然必须交付一个可独立运行的 HTML 文件。

## 十三、视觉质量验收标准

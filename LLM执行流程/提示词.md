# 项目名称：LLM 大语言模型工作原理 —— 3D 交互式可视化实验室

## 一、项目目标

使用 HTML5 + CSS3 + JavaScript + Three.js 开发一个高质量、科技感、沉浸式的 3D 交互可视化网站。

主题为：

**《从用户输入到 AI 输出：大语言模型（LLM）的完整工作流程》**

网站需要完整展示用户向大语言模型发送消息后，模型内部经历的所有核心处理步骤，以及最终生成文本并返回给用户的全过程。

不要将其制作成普通的静态流程图，而是制作成一个具有 3D 场景、粒子动画、数据流动、模块拆解、动态演示和交互探索能力的技术可视化作品。

目标用户是具有一定编程基础、但对大模型底层原理了解不深入的开发者。

要求既有视觉冲击力，也要具备准确、易懂的技术知识讲解。

## 二、整体视觉设计

1. 使用 Three.js 构建核心 3D 场景。
2. 整体采用深色科技风格，背景为深空黑色或深蓝色。
3. 使用蓝色、青色、紫色作为主要科技光效。
4. 使用 Bloom、粒子、辉光、线条流动等效果增强视觉表现。
5. 页面采用类似科幻 AI 神经网络实验室的设计风格。
6. 所有核心处理模块都以悬浮的 3D 节点、透明玻璃面板或立体结构呈现。
7. 模块之间通过发光管线连接，使用动态粒子表示 Token、向量和数据流。
8. 鼠标可以旋转、缩放和拖拽 3D 场景。
9. 点击任意模块，可以打开详细的原理说明面板。
10. 页面需要适配桌面端和移动端。

## 三、核心内容：完整的大模型处理流程

请按照以下阶段设计整个 3D 可视化流程。

### 第一阶段：用户输入（User Input）

展示用户在聊天窗口中输入一段自然语言，例如：

「人工智能是如何理解人类语言的？」

动画表现：

- 用户输入文字逐字出现。
- 消息通过发光的数据通道发送到 AI 系统。
- 输入文本被封装成请求数据包。
- 展示 Prompt、System Prompt、历史对话上下文等概念。

知识说明：

- 什么是 Prompt？
- 什么是上下文 Context？
- 什么是 System Prompt？
- 多轮对话如何携带历史消息？
- 模型接收到的并不一定只是用户当前输入，而是经过组织的完整输入序列。

### 第二阶段：文本预处理与 Tokenization（分词）

展示自然语言进入 Tokenizer。

动画表现：

- 一段完整文本从左向右流动。
- 文本被拆分成不同颜色的 Token 块。
- 每个 Token 显示对应的 Token ID。
- 展示 Token 与原始文字之间的映射关系。
- 展示 Token 数量统计。

知识说明：

- 什么是 Token？
- 什么是 Tokenizer？
- BPE、WordPiece、Unigram 等常见分词算法。
- 为什么一个汉字不一定对应一个 Token？
- 为什么一个英文单词可能被拆分成多个 Token？
- Token ID 是什么？
- Token 与字符、单词之间有什么区别？

### 第三阶段：Embedding（词向量嵌入）

展示 Token ID 进入 Embedding 层。

动画表现：

- 不同 Token ID 进入一个三维矩阵。
- 每个 Token 转换成高维浮点数向量。
- 用 3D 向量空间展示不同 Token 的位置。
- 向量由数字流组成，逐渐形成高维数据结构。
- 展示 Embedding Matrix 的查表过程。

知识说明：

- 什么是 Embedding？
- Token ID 如何映射成向量？
- 为什么计算机不能直接理解文字？
- 什么是向量维度？
- 什么是语义空间？
- 为什么语义相近的词在训练后的表示空间中可能具有相似特征？

### 第四阶段：位置编码（Positional Encoding）

展示位置信息如何加入 Token Embedding。

动画表现：

- 多个 Token 向量排列成序列。
- 每个 Token 获得对应的位置编码。
- 通过颜色变化和向量叠加动画展示位置信息注入。
- 展示输入序列的位置编号 0、1、2、3……

知识说明：

- 为什么 Transformer 需要位置信息？
- 什么是 Positional Encoding？
- 什么是 Sinusoidal Position Encoding？
- 什么是 RoPE（旋转位置编码）？
- 不同位置编码方案的区别。

注意：现代模型并不一定使用传统正弦位置编码，应解释不同架构采用的位置编码方案。

### 第五阶段：Transformer 核心架构

这是整个网站最重要的部分，需要重点设计。

使用大型 3D Transformer 模型作为场景中心。

展示完整的数据处理链路：

Input Embeddings
↓
Normalization
↓
Multi-Head Attention
↓
Residual Connection
↓
Normalization
↓
Feed Forward Network（FFN / MLP）
↓
Residual Connection
↓
Transformer Block Output

知识说明：

- 什么是 Transformer？
- Transformer 为什么能够处理自然语言？
- 什么是 Encoder？
- 什么是 Decoder？
- Encoder-Decoder 架构是什么？
- GPT 为什么主要采用 Decoder-only 架构？
- 什么是 Transformer Block？
- 为什么需要堆叠多个 Transformer Block？
- LayerNorm / RMSNorm 的作用。
- Residual Connection 的作用。
- Feed Forward Network 的作用。

提供 3D Transformer Block 拆解功能。

点击 Transformer 模块，可以将其展开，逐层观察内部结构。

### 第六阶段：Self-Attention（自注意力机制）

这是第二个重点模块，需要制作非常直观的 3D 动画。

展示 Q、K、V 的生成过程。

动画流程：

输入向量
↓
通过三个不同的线性变换
↓
生成 Query、Key、Value
↓
计算 Q × K 转置
↓
除以 √dₖ
↓
Softmax
↓
得到 Attention 权重
↓
Attention 权重 × V
↓
得到 Attention 输出

动画表现：

- 一个 Token 生成 Q、K、V 三组向量。
- 不同 Token 之间建立动态连接。
- 根据 Attention 权重改变连接线的粗细和亮度。
- 高权重连接使用明亮光线，低权重连接使用暗色线条。
- 展示 Attention Score 矩阵。
- 展示 Softmax 前后的权重变化。
- 点击任意 Token，可以观察它与其他 Token 的注意力关系。

知识说明：

- Query、Key、Value 分别是什么？
- 为什么需要 Q、K、V？
- Attention Score 如何计算？
- Softmax 的作用是什么？
- 为什么要除以 √dₖ？
- Self-Attention 如何捕捉上下文关系？
- Causal Mask 是什么？
- 为什么 GPT 不能直接关注未来 Token？

### 第七阶段：Multi-Head Attention（多头注意力）

动画表现：

- 将一个 Attention 模块拆分成多个并行的 Head。
- 每个 Head 使用不同颜色。
- 不同 Head 展示不同的注意力连接模式。
- 最后将各个 Head 的结果进行拼接。
- 通过线性变换得到最终输出。

知识说明：

- 为什么需要多个 Attention Head？
- 不同 Head 是否可以学习不同类型的关系？
- Head 数量与模型能力有什么关系？
- Concatenate 和 Linear Projection 的作用。

### 第八阶段：多层 Transformer Block 堆叠

动画表现：

- 展示多个 Transformer Block 垂直堆叠。
- Token 数据依次穿过每一层。
- 每一层都出现动态计算动画。
- 展示浅层、中层、深层的特征变化。
- 可以自由选择某一层进行放大和拆解。

知识说明：

- 为什么大模型需要几十层甚至上百层？
- 每一层的输入和输出是什么？
- 隐藏状态 Hidden States 是什么？
- 参数量与模型层数有什么关系？

### 第九阶段：LM Head 与 Logits

展示 Transformer 最后一层的输出进入 LM Head。

动画表现：

- 最后一层 Hidden States 进入线性投影层。
- 输出转换为词表维度的 Logits。
- 展示一个包含不同 Token 的概率分布柱状图。
- 展示 Logits 和概率之间的关系。

知识说明：

- 什么是 LM Head？
- 什么是 Logits？
- 什么是 Vocabulary？
- 为什么输出维度通常与词表大小有关？
- 为什么模型输出的不是直接的自然语言文本？

### 第十阶段：概率计算与采样（Sampling）

动画表现：

- 将 Logits 通过 Softmax 转换为概率分布。
- 展示不同候选 Token 的概率。
- 按概率分布动态选择下一个 Token。
- 展示 Temperature 对概率分布的影响。
- 展示 Top-K 和 Top-P 筛选过程。
- 最终高亮被选中的 Token。

知识说明：

- Softmax 如何计算概率？
- Temperature 是什么？
- Top-K Sampling 是什么？
- Top-P / Nucleus Sampling 是什么？
- Greedy Decoding 是什么？
- Beam Search 是什么？
- 为什么同一个 Prompt 多次生成的结果可能不同？

### 第十一阶段：自回归生成（Autoregressive Generation）

动画表现：

- 模型生成第一个 Token。
- 将新生成的 Token 追加到已有序列。
- 再次进入模型进行下一轮推理。
- 循环执行 Token 生成过程。
- 每次生成都展示 Token 数量和生成进度。
- 最终拼接成完整句子。

重点展示：

Input → Predict Next Token → Append Token → Predict Next Token → ...

知识说明：

- 什么是自回归生成？
- 为什么大模型是一个 Token 一个 Token 地生成？
- 什么是 KV Cache？
- 为什么 KV Cache 可以减少重复计算？
- 什么是 Prefill 阶段？
- 什么是 Decode 阶段？
- 为什么首 Token 延迟和后续 Token 生成速度不同？

### 第十二阶段：解码与文本还原（Detokenization）

动画表现：

- 多个 Token ID 汇聚到解码模块。
- Token ID 映射回对应的 Token 文本。
- Token 逐渐拼接成完整句子。
- 展示 Token 与最终文本之间的映射关系。

知识说明：

- 什么是 Detokenization？
- Token ID 如何还原成文本？
- 为什么 Token 边界不一定对应自然语言单词边界？

### 第十三阶段：停止条件与结果返回

动画表现：

- 模型检测 EOS（End Of Sequence）等停止条件。
- 达到停止条件或生成长度限制后结束生成。
- 将最终文本通过数据通道返回用户。
- 聊天界面逐字显示 AI 的回答。
- 展示本次推理的 Token 数量、生成耗时、输出长度等模拟统计数据。

知识说明：

- EOS Token 是什么？
- 最大生成长度 Max Tokens 是什么？
- Stop Sequence 是什么？
- 流式输出 Streaming 是什么？
- SSE / WebSocket 在应用层如何将生成内容传给前端？
- 模型推理结束和前端收到完整响应之间有什么区别？

## 四、补充：真实大模型推理中的基础设施

## 八、技术准确性要求

这是一个技术科普项目，准确性比炫酷效果更加重要。

特别注意：

1. 不要把所有大模型都描述成 GPT Decoder-only 架构。
2. 明确区分 Encoder-only、Decoder-only 和 Encoder-Decoder。
3. GPT 类模型通常采用因果注意力机制。
4. 训练过程和推理过程必须区分。本项目主要演示推理过程。
5. 不要把 Tokenization、Embedding 和 Attention 混为一谈。
6. 不要把 Logits 直接称为概率。
7. 不要把 Temperature、Top-K、Top-P 混为一谈。
8. 不要将 KV Cache 描述成保存完整对话历史。
9. 不要把 GPU 并行计算描述成完全串行的过程。
10. 说明不同模型在位置编码、归一化、注意力实现和采样策略上存在差异。
11. 区分模型内部推理和应用服务层的请求处理、流式传输。
12. 明确说明 3D 数据与动画是原理演示和模拟数据，不代表真实模型内部实时张量的完整可视化。
